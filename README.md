## Flujo de trabajo con Git
### Inicio de la sesión
Antes de comenzar a trabajar, es imprescindible sincronizar tu repositorio local con los últimos cambios del equipo:
```bash
    git checkout develop
    git pull origin develop
```
### Creación de una funcionalidad
**!!!Nunca se debe trabajar directamente sobre las ramas `develop` o `main`¡¡¡**
Para cada nueva tarea o funcionalidad, crea una rama específica:
```bash
    git checkout -b feature/nombre-de-la-funcionalidad
```
### Realizar commits
Realiza commits frecuentes con mensajes claros y descriptivos que indiquen el cambio realizado:
```bash
    git add .
    git commit -m "Add: lógica de salto en Player.gd"
```
Se recomienda seguir una convención como:
- `Add:` nueva funcionalidad  
- `Fix:` corrección de errores  
- `Update:` modificaciones o mejoras  
- `Refactor:` cambios internos sin afectar funcionalidad  
### Subir cambios al repositorio
Una vez realizados los commits, sube tu rama al repositorio remoto:
```bash
    git push origin feature/nombre-de-la-funcionalidad
```
### Crear Pull Request
Crea un **Pull Request (PR)** desde tu rama `feature` hacia `develop`.
El PR debe incluir:
- Descripción de lo implementado (breve resumen) 
- Objetivo de la funcionalidad  
### Revisión y merge
Antes de integrar los cambios en `develop`, se debe:
- Revisar el código
- Resolver posibles conflictos  
- Validar que todo funciona correctamente

Este paso de revisión y validacion lo hara el integrante **Michael**, una vez que este validada y no
haya errores se procedera a hacer el merge correspondiente.
